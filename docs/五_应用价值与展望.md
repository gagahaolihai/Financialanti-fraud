> 本文档为「反诈卫士 v3.0」参赛材料的第五部分。

> **数据口径声明：** 系统性能与准确率指标全部取自本仓库 `evaluation/results/` 下的实测报告，随文标注样本量与限定语；行业数据全部标注来源机构、报告名称与年份；凡属**测算值**而非实测值的，均明确标注「测算」并列出计算过程。

## 1. 应用场景

反诈卫士 v3.0 的核心能力可概括为**三类**：**识别**（意图 + 风险 + 诈骗类型）、**解释**（依据来源归属 + 知识检索）、**干预**（分级劝阻话术 + 举报与情景训练）。

这三类能力在四个典型场景中落地。每个场景均给出**具体操作流程**与**量化价值测算**。

### 1.1 场景一：社区反诈宣传站（面向街道 / 派出所 / 社区服务中心）

**场景痛点：** 基层反诈宣传主要靠发传单、贴海报、开讲座，形式单向、覆盖有限、无法针对个体答疑。民警上门劝阻成本高——据公安部通报，2025 年全国累计见面劝阻 **674.7 万人次**，人力投入巨大。

**落地形态：** 在社区服务中心、党群服务站部署一台**离线一体机**（普通办公电脑即可，无需联网），居民自助咨询。

**操作流程：**

| 步骤 | 居民操作 | 系统响应 |
|---|---|---|
| 1 | 在触摸屏上描述遇到的情况（可直接口述语音转文字，或手写输入） | 3 秒内返回风险等级与依据来源 |
| 2 | —— | 若判定 **high / critical**，立即展示分级劝阻话术 + 96110 一键拨号 |
| 3 | —— | 同时展示"你遇到的属于哪一类骗局""这类骗局共有哪些套路"（16 要素知识卡片） |
| 4 | 点击"我想学更多" | 进入 12 个情景剧本之一，做互动闯关训练 |
| 5 | 完成后 | 获得积分与勋章，可打印"反诈学习凭证" |

**量化价值（测算）：**

| 维度 | 测算 | 依据 |
|---|---|---|
| 单次咨询成本 | **≈ 0 元** | 本地模式零 API 调用、零网络费用；仅摊薄设备电费 |
| 单机并发能力 | **448 QPS**（单线程实测） | `evaluation/results/benchmark_report.md` |
| 单次响应耗时 | **2.23 ms**（规则引擎路径实测） | 同上 |
| 单台设备日服务量测算 | 按每台每天开放 8 小时、单次咨询含阅读回复约 90 秒、并发 1 人计 → **约 320 人次/台/日** | 测算：8×3600÷90 ≈ 320 |
| 对比人工咨询 | 一名社区民警/网格员日均接待咨询约 20–30 人次 → 单台设备**等效约 10–16 名人力**的接待量 | 测算：320 ÷ 20~30 ≈ 10.7~16 |

> **口径说明：** 448 QPS 与 2.23 ms 为**规则引擎路径**的单线程实测值，不含外部大模型网络往返。上面的"日服务量"是**按人工接待节奏测算的体验上限**，不是系统吞吐上限——系统的技术吞吐远高于此，瓶颈在人机交互时长而非算力。

### 1.2 场景二：校园反诈教育（面向高校 / 中学 / 教育局）

**场景痛点：** 校园是刷单返利、校园贷、游戏交易、冒充熟人等骗局的高发区。传统做法是开学季开一次讲座、签一份承诺书，学生参与度低、效果难量化。同时，学生群体对"被强制安装 App"普遍抵触。

**落地形态：** Web 应用（浏览器直接访问，无需安装）+ 可选 PWA 添加到桌面。可嵌入学校安全教育平台，或作为"反诈主题班会"的互动工具。

**操作流程：**

| 步骤 | 教师/学生操作 | 系统响应 |
|---|---|---|
| 1 | 教师布置："进入情景闯关，完成'刷单陷阱'与'校园贷危机'两关" | 学生浏览器打开链接即可，零安装 |
| 2 | 学生逐关选择应对方式 | 系统对每个选择给出即时反馈与后果推演 |
| 3 | 完成后 | 生成个人反诈积分与勋章（`scenario_beginner` 等） |
| 4 | 教师查看班级榜单 | 按积分排行，可视化学情 |
| 5 | 学生自由提问 | 7×24 小时对话答疑；复杂问题可接外部大模型增强（学校自选是否开启） |

**量化价值（测算）：**

| 维度 | 数值 | 依据 |
|---|---|---|
| 可训练情景 | **12 个剧本 / 36 个决策步** | `knowledge_base/scenarios.json` 实测 |
| 覆盖诈骗类型 | **16 类** | `knowledge_base/fraud_types.json` 实测 |
| 单场班会覆盖 | 按 50 人班级、每人 2 关、每关 3 步、约 10 分钟 → **1 个课时完成全班训练并出成绩** | 测算 |
| 学情可量化 | 积分 + 勋章 + 排行榜，教师端可见 | `gamification/` 已实现 |
| 安装抵触 | **零安装**（Web / PWA） | 无需应用商店，无需人脸识别注册 |

> **对比说明：** 现有主流反诈 App 需下载安装、实名注册、常驻后台权限，在校园场景中常引发"被强制安装"的抵触情绪（详见 §2.3 竞品局限）。本项目采用 **Web 优先、零安装**形态，正是针对这一痛点。

### 1.3 场景三：银行网点 / 支付机构柜面（面向大堂经理 / 柜员）

**场景痛点：** 银行柜面是拦截转账的**最后一道闸门**。柜员面对被深度洗脑的客户时，缺少即时、权威、可展示的劝阻依据——客户常反问"你凭什么说这是诈骗"。

**落地形态：** 部署在大堂平板或柜面终端，作为**柜员辅助工具**（而非替代柜员判断）。

**操作流程：**

| 步骤 | 柜员操作 | 系统响应 |
|---|---|---|
| 1 | 客户要求大额转账，柜员察觉异常，在系统输入客户描述的原话 | 返回风险等级 + **触发规则明细**（哪条规则、权重多少） |
| 2 | 将屏幕转向客户 | 展示"依据来源"：命中的诈骗类型、匹配的关键词、该类骗局的 79 条典型话术中的相似片段 |
| 3 | —— | 展示该类骗局的**真实案例**（23 条案例库）与**法律后果**（8 部法规） |
| 4 | 若客户仍在犹豫 | 调出**分级干预话术**，按 `critical` / `high` 给出对应劝阻脚本 |
| 5 | 客户配合后 | 可一键生成举报记录，沉淀到风险事件库 |

**量化价值（测算）：**

| 维度 | 数值 | 依据 |
|---|---|---|
| 判断依据可展示 | 每条命中规则含 **规则名 + 类别 + 权重 + 触发片段** | `risk_analyzer.analyze_risk()` 返回 `triggered_rules` |
| 风险研判 Precision | **100%**（自建集 40 条，修正口径） | `evaluation/results/AI效果测试报告.md` |
| 风险研判 F1 | **97.4%**（自建集 40 条） | 同上 |
| 依据来源可追溯 | 返回命中的诈骗类型、相对匹配度、命中关键词 | `knowledge_sources` 字段（本次新增） |
| 对比人工劝阻 | 公安部 2025 年紧急止付涉诈资金 **2170.7 亿元**；柜面拦截是止付的关键环节，工具化可缩短单次甄别耗时、提升柜员信心 | 公安部 2026-01-08 发布会 |

> **重要说明：** 本场景中系统定位为**柜员的辅助工具**，风险判断的最终责任仍在具备资质的金融从业人员。系统提供的是"可展示、可追溯的证据链"，而非替代决策。

### 1.4 场景四：家庭数字守护（面向子女 / 老年人本人）

**场景痛点：** 老年群体是诈骗的重点目标。据 CNNIC 第 56 次《中国互联网络发展状况统计报告》，我国 **60 岁及以上银发网民规模达 1.61 亿人**，老年群体互联网普及率 **52.0%**——过半老年人已上网，但数字素养与风险辨识能力普遍不足。

同时，老年人用手机有独特困难：**注册难、扫脸难、界面复杂**。现有反诈 App 需实名注册 + 人脸识别，大量老年人卡在第一步。

**落地形态：** 面向老年人的**极简对话界面**——无需注册、无需人脸识别、打开即用；大字号、高对比度、语音优先。

**操作流程：**

| 步骤 | 老人操作 | 系统响应 |
|---|---|---|
| 1 | 打开网页（子女可预先保存为桌面图标），直接说话或打字："我接到一个电话……" | 无需注册登录，直接进入对话 |
| 2 | —— | 用**生活化语言**回复（系统提示词明确要求"对受害者和老年人要特别温和耐心，先安抚再给建议"） |
| 3 | —— | 若紧急，**回复开头即标 🚨 并给出立即行动步骤**（挂断、不转账、拨 96110） |
| 4 | 老人把"自称银行客服"的短信验证码对话说出来 | **隐私卫士检测到验证码 → 立即告警并脱敏**，同时判定为高危 |
| 5 | 发送可疑截图 | **截图 OCR 识别**，检出伪造法律文书、可疑 App、虚假客服等特征 |

**量化价值（测算）：**

| 维度 | 数值 | 依据 |
|---|---|---|
| 潜在服务人群 | **1.61 亿**银发网民 | CNNIC 第 56 次报告（2025-07-21） |
| 使用门槛 | **零注册、零扫脸、零安装** | 直接访问 Web 页面 |
| 隐私保护 | 9 类 PII 自动检测 + 会话级加密脱敏，**数据不出本机** | `engine/privacy_guard.py` |
| 紧急场景响应 | 2.23 ms 内出风险等级，**不被网络往返拖慢** | 规则引擎路径实测 |
| 老人最需的"耐心解释" | 单次回复 300–900 字，含识别要点 + 防范建议 + 行动步骤 | 端到端实测（本地模式 677 字 / 增强模式 945 字） |

> **隐私设计的价值：** 老年人求助时往往主动提供身份证号、银行卡号。常规产品把这些数据"存下来"，本项目则**反向告警**——立即提醒"你刚才泄露了敏感信息，请勿再向任何人提供"。这把隐私风险转化为一次**教育时机**。

### 1.5 场景小结

| 场景 | 部署形态 | 核心能力 | 关键量化指标 |
|---|---|---|---|
| 社区宣传站 | 离线一体机 | 自助识别 + 情景训练 | 448 QPS / 2.23 ms / 等效 10–16 名人力接待量（测算） |
| 校园教育 | Web + PWA | 情景闯关 + 学情量化 | 12 剧本 / 36 决策步 / 零安装 |
| 银行柜面 | 柜面终端 | 证据链展示 + 干预话术 | Precision 100% / F1 97.4%（自建集 40 条） |
| 家庭守护 | 极简 Web 页 | 零门槛对话 + 隐私告警 | 1.61 亿潜在人群 / 零注册 / 数据不出本机 |

**四个场景的共同技术底座：** 全部由**同一套系统**支撑，通过配置切换形态——不需要为每个场景单独开发。默认**本地智能模式**保证"数据不出本机"，仅在用户显式启用时才接入外部大模型。

## 2. 市场分析

### 2.1 需求侧：电信网络诈骗的规模

电信网络诈骗已是**高发、高损、跨地域**的突出犯罪类型。以下为权威机构公布的近期数据：

| 指标 | 数值 | 来源 |
|---|---|---|
| 2025 年全国侦破电信网络诈骗案件 | **25.8 万起** | 公安部新闻发布会，2026-01-08（[央广网](https://news.cnr.cn/native/gd/kx/20260108/t20260108_527486779.shtml)、[光明网](https://m.gmw.cn/2026-01/08/content_1304295463.htm)） |
| 2025 年紧急止付涉诈资金 | **2170.7 亿元** | 同上 |
| 2025 年拦截诈骗电话 / 短信 | **36 亿次 / 33 亿条** | 同上 |
| 2025 年累计见面劝阻 | **674.7 万人次** | 同上 |
| 2025 年 1–11 月检察机关起诉电诈犯罪 | **6.2 万人** | 最高检全国检察长会议，2026-01-19（[四川长安网](https://www.sichuanpeace.gov.cn/gcsy/20260119/2994624.html)） |
| 2025 年全年起诉电诈犯罪 | **68,907 人** | 最高检《刑事检察工作白皮书（2025）》，2026-03-10 |
| 涉缅北专项：批准逮捕 / 提起公诉 | **4.8 万人 / 4.7 万人**（2023 年以来） | 同上 |

**需求侧的三个判断：**

1. **案件存量巨大且持续**——25.8 万起破案量对应的是**已被侦破**的部分，实际发案量更高。2170.7 亿元的紧急止付资金说明涉诈资金规模巨大。
2. **人力劝阻已近瓶颈**——674.7 万人次见面劝阻意味着巨量的基层警力投入，**边际成本高、难以线性扩展**。AI 在"初筛 + 标准化答疑"环节有明确替代空间。
3. **事后拦截为主，事前预防不足**——拦截 36 亿次电话、33 亿条短信属于**通信侧的事后/事中拦截**；用户**事前**遇到可疑情形时的即时咨询渠道仍然稀缺。

> **注意：** 公安部发布会公布的是"紧急止付涉诈资金 2170.7 亿元"，**并非"群众损失总额"**——公开渠道未披露损失总额口径，本文档不对此做推算。

### 2.2 政策侧：法规明确了义务，也打开了空间

《中华人民共和国反电信网络诈骗法》于 **2022-09-02 通过、2022-12-01 施行**，对互联网服务提供者设定了一系列可执行的义务：

| 条款 | 要求 | 对本项目的意义 |
|---|---|---|
| **第 21 条** | 互联网接入、域名注册、服务器托管、即时通讯、网络交易、网络直播、广告推广等服务须**实名制**，不提供真实身份信息不得提供服务 | 系统的"零注册"形态适用于**公众咨询工具**定位；若作为平台化服务嵌入，需补充实名模块 |
| **第 25 条第 2 款** | 互联网服务提供者应履行**合理注意义务**，对网络资源服务、推广服务、应用/网站制作维护、支付结算等涉诈支持帮助活动进行**监测识别和处置** | 直接对应系统的**风险识别 + 举报分析**能力 |
| **第 22 条** | 对涉诈异常账号可重新核验，采取限制功能、暂停服务、关闭账号等处置 | 系统的风险事件库可作为处置依据 |
| **第 24 条** | 域名解析、跳转、网址转换服务须核验真实性并**留存日志、支持溯源** | 系统的链接检测 + 审计日志能力可对接 |
| **第 26 条** | 须配合公安调取证据，发现涉诈线索应**移送**公安、金融、电信、网信部门 | 系统的举报中心 + 结构化数据可供对接 |
| **第 41–43 条** | 违反实名制/监测处置义务：5 万–50 万元罚款，情节严重 50 万–500 万元并可**关闭网站或 App** | 合规是刚性需求，非可选 |

**政策侧的判断：** 法规把"监测识别和处置涉诈活动"从**道德倡议**变成了**法律义务**，对互联网平台是**合规成本**。这意味着**面向 B 端的反诈能力供给存在真实付费意愿**——这是本项目从 C 端工具向 B 端能力输出延伸的市场基础。

### 2.3 竞争侧：现有反诈产品的局限

**主要竞品：国家反诈中心 App**（公安部刑侦局指导、公安部防范电信网络诈骗信息监控中心运营）

| 维度 | 数据 | 来源 |
|---|---|---|
| 下载量 | 约 **1.4 亿次** | 腾讯应用宝页面 |
| 累计注册用户 | 突破 **1.2 亿**（第三方口径，非公安部官方声明） | 多特软件站页面（2025-12-30 更新） |
| 累计受理举报线索 | **3172 万条** | 百度百科词条（官方转载口径） |
| 累计预警次数 | **4.2 亿次** | 同上 |
| 2021-06 官方数据 | 全国注册用户超 **6500 万**，预警 2300 万次 | 公安部消息（[济南市政府转载](https://www.jinan.gov.cn/col22234/art/2021/art_22234_4872254.html)） |
| 2025 年新增功能 | AI 智能通话守护、境外来电智能拦截 | App 更新日志 |

> **数据可靠性说明：** "1.2 亿注册用户""1.4 亿下载量"来自第三方应用商店页面，**非公安部直接发布的官方累计数据**；官方口径更多是"累计受理举报线索 3172 万条、预警 4.2 亿次"这类运营数据。

**用户反馈中反映出的局限（来自应用商店评论区、知乎讨论等公开渠道的真实用户反馈）：**

| 局限 | 具体表现 | 公开来源 |
|---|---|---|
| **误报 / 一刀切拦截** | "把我正常信息给拦了"；连**顺丰快递电话、工作陌生来电**都被拦截，导致快递联系不上 | 应用汇评论区、OPPO 应用站评测 |
| **事后预警为主** | 用户反映"装完后接到境外诈骗电话，**来电挂断后才收到**风险提示短信" | 知乎问答（147 万浏览） |
| **注册门槛高** | 人脸识别反复失败；"想举报诈骗短信，注册扫脸十几次都失败"——**老人根本卡在第一步** | 应用商店评论区、FoxData 数据页 |
| **性能体验问题** | 人脸识别卡顿、闪退、频繁提示"网络不好" | 应用汇评论区 |
| **强制安装引发抵触** | "上头强制要求下载""完成任务罢了"；大量差评源于强制推广本身 | 应用汇评论区、知乎讨论 |
| **缺少对话式答疑** | 产品形态以**预警 + 举报**为主，用户遇到"这算不算诈骗"的模糊情形时，缺少可即时交互的咨询入口 | 综合产品形态判断 |

**本项目的差异化定位：**

| 对比维度 | 国家反诈中心 App | 反诈卫士 v3.0 |
|---|---|---|
| 产品形态 | 移动 App，需下载安装 | **Web 优先，零安装**（可选 PWA） |
| 使用门槛 | 实名注册 + 人脸识别 | **零注册，打开即用** |
| 交互方式 | 预警 + 举报为主 | **对话式咨询**（可问"这算不算诈骗"） |
| 隐私处理 | 数据上传至中心平台 | **默认本地运行，数据不出本机** |
| 解释能力 | 提示"疑似诈骗" | **给出依据来源**：命中哪类骗局、哪些关键词、哪些规则、权重多少 |
| 适老化 | 需完成注册流程 | **大字号 + 语音优先 + 无需注册** |
| 教育功能 | 以宣传内容为主 | **12 个情景剧本互动闯关 + 积分勋章** |
| 部署灵活度 | 中心化 App | **可离线部署到社区一体机、柜面终端** |
| 外部大模型 | —— | **可选接入，默认关闭**，用户自主决定 |

> **定位说明：** 本项目**不与国家反诈中心 App 竞争**，而是互补——国家反诈中心 App 强在**国家级数据汇聚、跨部门联动、通信侧拦截**；本项目强在**本地化、可解释、零门槛、可嵌入具体场景**。理想的落地形态是作为**基层场景的补充工具**，而非替代国家级平台。

### 2.4 市场机会与商业模式设想

**目标客户与需求：**

| 客户类型 | 需求 | 付费逻辑 |
|---|---|---|
| 街道 / 社区 / 派出所 | 反诈宣传效果可视化、减轻基层负担 | 政府采购 / 综治经费 |
| 高校 / 中学 / 教育局 | 校园反诈教育可量化、学生不抵触 | 教育信息化预算 |
| 银行网点 / 支付机构 | 履行《反诈法》第 25 条合理注意义务、柜面拦截工具 | **合规刚需**，IT 预算 |
| 互联网平台 | 第 25 条监测识别与处置义务 | **合规刚需** |
| 养老服务 / 保险公司 | 老年客户风险教育与增值服务 | 增值服务预算 |

**三种可行的商业模式：**

1. **软件授权 + 私有化部署**——面向银行、互联网平台等有合规刚需的机构，一次性授权 + 年度维护。核心卖点是**可离线部署、数据不出本机**，恰好契合金融机构的数据合规要求。
2. **场景化 SaaS / 一体机**——面向社区、学校，提供预装一体机或轻量 SaaS，按点位/年收费。
3. **能力输出（API）**——将风险研判、知识检索、依据来源归属封装为 API，供第三方系统集成。系统的 `/api/chat` 已返回结构化的 `risk_level` / `fraud_type` / `knowledge_sources` / `triggered_rules`，天然适配此类输出。

**市场规模的定性判断（不做无依据的数值预测）：**

- **需求确定性高**：25.8 万起破案量、2170.7 亿元止付资金表明问题规模真实且巨大；
- **政策强驱动**：《反诈法》第 41–43 条把合规义务与**最高 500 万元罚款、关闭 App** 的处罚绑定，B 端需求是刚性的；
- **竞品留有空隙**：现有产品集中在**国家级平台 + 移动 App**形态，**本地化、可解释、零门槛、可嵌入具体场景**的方向竞争尚不激烈；
- **适老化的增量空间**：1.61 亿银发网民、52.0% 老年互联网普及率，而这部分人群恰恰是现有产品**注册门槛最高、最不友好**的对象。

> **诚实披露：** 本项目目前**未做市场规模测算的商业调研**，也**未与任何潜在客户建立付费合作**。上述为基于公开数据的机会判断，不构成对商业收入的预测。

### 3.3 本次改进的工程成果

在参赛准备过程中，项目完成了一轮**以可复现性问题为导向**的排查与修复。**这些问题不是功能设计缺陷，而是真实存在、可复现、已修复的工程缺陷**——列出它们比只列成绩更能说明工程能力。

| 编号 | 问题 | 根因 | 修复 |
|---|---|---|---|
| **B1** | 应用无法启动 | `.venv` 从另一台机器整包拷入，`pyvenv.cfg` 中记录的基础解释器路径在本机不存在 | 重写 `pyvenv.cfg` 指向本机同版本（3.11.4）Python，依赖全部存活，无需重装 |
| **B2** | 一键启动脚本报 `ModuleNotFoundError` | `run_local.bat` 使用系统 `py -3.11`，而依赖全部安装在项目内 `.venv` | 改为硬编码 `.venv\Scripts\python.exe`，并在解释器缺失时给出重建指引 |
| **B3** | **`.env` 配置文件完全失效** | `load_dotenv()` 位于文件末尾，而 `Config` 类体中的 `os.getenv()` 在 `import` 时已求值完毕 | 将 `load_dotenv()` 移至 `Config` 类定义**之前**。实测验证：修复前 `.env` 中 `PORT=19999` 被忽略，修复后正确生效 |
| **B4** | 知识检索返回"匹配度 160%" | 混合检索融合两路**量纲不同**的分数（语义 0~1 vs 关键词累加分上不封顶），未归一化；越界值被格式化为百分比写入大模型提示词 | 各路分数先归一化再加权；对外分数恒在 `[0,1]`，权重仅参与排序。**修复后 Top-1 命中质量提升**（"刷单返利"从第 2 位升至第 1 位） |
| **B5** | API 基础地址被当作完整端点 | `.env.example` 提供的是基础地址（`https://api.deepseek.com/v1`），代码直接用作 POST 全地址 | 新增 `normalize_api_url()`，兼容基础地址与完整端点两种写法（5 个用例全部通过） |
| **B6** | 管理后台鉴权装饰器定义了但从未使用 | `admin_required` 存在但所有 `/api/admin/*` 均未挂载 | 为其增加"未配置管理员密码时放行、配置后严格校验"的降级逻辑，并挂载到 4 个新增的敏感端点 |
| **B7** | 配置存储自锁死 | `save()` 持有 `Lock` 后调用 `load()` 再次获取同一把锁 | 改用 `threading.RLock`（可重入锁） |
| **B8** | 截图诈骗检测完全不可用 | EasyOCR 模型目录为空，且模型托管在 GitHub Releases（本机网络不可达） | 通过镜像代理下载 3 个模型（`craft_mlt_25k` / `zh_sim_g2` / `english_g2`），并校验 CRC；`/api/health` 的 `multimodal_ocr` 已为 `true` |
| **B9** | RAG 引擎与主应用持有两个独立的大模型客户端 | 热切换配置时只刷新其中一个，出现"后台显示已启用、RAG 仍走规则" | 新增 `set_llm_client()` 注入，两边**共用同一实例** |

**同时修正的一处评测方法论缺陷（非代码缺陷）：** 真实数据评测脚本存在**跨样本共用 `user_id` 导致历史累积污染**、**未传意图参数导致门控失效**两处方法缺陷，使首轮风险指标（F1 69.2%）不可信。修正后同一批真实数据 F1 升至 **100%**（15 正例，样本量警示见 §3.1）。

### 3.4 诚实性说明

为避免夸大，以下三点在参赛材料中逐项明确：

1. **语义模型来源**——项目内 `paraphrase-multilingual-MiniLM-L12-v2` 是 **HuggingFace 公开发布的预训练模型**，仓库内**不含任何训练或微调脚本**。本项目**自建**的部分是：FAISS 向量索引、15 类零样本意图锚点、16 类诈骗知识库（16 要素结构）、287 条对话句式规则、22 条风险研判规则。**参赛材料一律不称"自训练模型"。**
2. **真实数据的样本量限制**——真实集仅 18 条"有类型"样本、15 条风险正例，100% 的**置信区间很宽**，报告原文已明确"**不应外推为生产准确率**"。更稳健的参考是自建集（64 条 / 40 条）的数字。
3. **多版本指标不合并**——消融实验（09:17，融合阈值 0.5）与 AI 效果测试（16:55，融合阈值 0.7）为**不同版本**，本文档不合并两者的数字，引用时均标注出处与时间。

### 3.5 已识别但尚未解决的问题

| 问题 | 现状 | 影响 |
|---|---|---|
| 融合策略未体现增益 | 消融实验显示"融合 77.1% < 纯语义 81.4%" | 融合阈值/权重需进一步调优（报告原文已列为后续方向） |

### 4.4 技术演进的三个判断

1. **本地优先不会过时，反而更重要。** 反诈咨询涉及用户的身份证号、银行卡号、被骗经历——这些数据的敏感性决定了**能本地处理就不要上云**。本项目"默认本地 + 可选外部增强"的架构，在任何数据合规趋严的背景下都更具生命力。

2. **可解释性是反诈产品的信任基础。** 用户被诈骗分子深度洗脑时，一句"系统判定这是诈骗"毫无说服力；而"你遇到的属于**冒充公检法**，命中了『**安全账户**』『**洗钱**』这两个特征词，这类骗局的典型话术有 79 条与你描述高度相似，2025 年全国有大量同类案例"——**证据链才能说服人**。依据来源归属不是锦上添花，而是产品的核心价值。

3. **通用大模型替代不了垂直的规则与知识。** 大模型能生成流畅的回复，但**不能保证风险研判的确定性**——劝阻场景下漏报一次的代价远大于答得不够漂亮。本项目把大模型定位为"知识咨询类的增强"，而把**风险研判留在确定性的规则引擎**上，正是基于这一判断。
